# Repository guidelines

## Code

- Write all project content in English, including code, documentation, identifiers, comments, docstrings, and tests.
- Keep the code modular, readable, and consistent with the language and framework's established best practices.
- Reuse reliable existing libraries and project utilities instead of reimplementing solved problems.
- Handle expected errors and edge cases, but avoid unnecessary abstractions and complexity.

## Tests and documentation

- Maintain a meaningful automated test suite. Add or update tests for behavior changes, and run the relevant tests before committing.
- Keep the README concise. Cover the project overview, installation, usage, tests, and directory structure; add detail only when it helps users.

## Git and pull requests

- Usually create a dedicated branch for development work instead of working directly on `main`.
- Use Conventional Commits for everyone, with no distinction between agent and human changes.
- Keep each commit focused, clear, and small enough to review comfortably. Agents must commit their own completed work locally and must never push.
- Give pull requests clear, concise titles and brief descriptions of their purpose, main changes, and tests.
